How approvals work across TASAF MIS, and how to decide the requests waiting for you. Changes that need a second person (an account application, a payment-detail correction, MUSE settings, a News Feed post) become an approval request. A request passes through its flow's steps in order; each step is decided by someone holding that step's right.

1. Purpose, Roles, and Access

RightGrants
240201The Approvals page.
240301Cancel a request.
240302Return a request for correction.
240303Decide a step on another approver's behalf (override).
240101 / 240102 / 240103See / manage / edit Approval Flows.

Deciding a step needs that step's own right as well, e.g. right 270903 to approve a MUSE settings change.

2. Key Concepts

TermMeaning
FlowThe approval route for one kind of change, e.g. account applications (Manager → ICT), MUSE settings changes, case payment changes, News Feed posts, trainings.
StepOne decision in a flow, with the right that authorizes it. Steps are sequential: each unlocks once the previous one is approved.
Distinct approversWhen set, the same person cannot decide two steps of one request.
RequesterThe person who made the change. They can never approve it.

3. My Approvals and All Requests

Open Approvals. My Approvals lists the requests whose current step you can decide; All Requests lists every request you may see. Filter by flow, status and date; double-click to open. Many requests also appear in the Tasks inbox, and deciding in either place has the same effect.

4. Decide a Request

The request page shows the flow and current step (Step 2 of 3 — waiting on ICT), What is being approved, and for settings changes a What will change table with each current and new value, plus the reason given.

  1. Read the change. Open record opens the record it concerns.
  2. Write a Decision note. It is required to reject, return or cancel, and visible to the next approver.
  3. Optionally add a Signature (your typed name or a reference).
  4. Choose Approve, Reject, or Return for correction (sent back to the requester to fix).

The History tab lists every decision with its note. When the last step is approved, the change is applied by the module it belongs to.

If the page says You are not the approver for the current step or You submitted this request, so another user must approve it, the buttons are hidden by design.

5. Approval Flows (Administrators)

Under Approval Flows, each flow lists its steps. Edit flow lets you add, remove or reorder steps, set each step's label and right, and require distinct approvers. A flow edited here is marked customised.

Every step's right must be granted to at least one role, otherwise nobody can approve it and requests wait forever.

6. Statuses

RequestMeaning
PendingA step is waiting for a decision
ApprovedEvery step approved; the change is applied
RejectedA step was rejected; nothing is applied
ReturnedSent back for correction
CancelledWithdrawn; nothing is applied

A step can also be Skipped when its flow says so.

7. Troubleshooting

ProblemWhat to do
