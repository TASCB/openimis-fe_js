How to bring the PSSN II historical records into TASAF MIS and look them up. The PSSN II registry is an archive: households and members imported from the legacy tasafMIS, kept for reference and comparison. They are not live TASAF MIS beneficiaries and are never written to the live registry tables.

Each page carries the banner PSSN historical archive — these records are not live TASAF MIS beneficiaries.

3. Import from CSV Files

  1. Open Legacy Imports and press + (Import legacy PSSN data).
  2. Choose CSV files (household + member exports).
  3. Drop or browse the Household file and the Member file; the two are uploaded together. Household template and Member template show the expected columns. Each file shows its rows and whether the required columns were found.
  4. Keep or edit the Batch code, which is generated automatically.
  5. Press Preview import, check the row counts and recognised columns, then import.
The two files together must be under 64 MB. A file missing a required column is refused before anything is imported.

4. Import from the Legacy API

  1. In the same dialog choose Legacy tasafMIS API.
  2. Choose the Region and District / PAA.
  3. Leave Dry run ticked and press Dry Run: it fetches and shows the rows, households and members, and imports nothing.
  4. Untick Dry run and press Start Import. Large districts run in the background.

5. Follow an Import Batch

The Legacy Imports list shows each batch's district or PAA, method (API or CSV), status, households, members, issues and date. Refresh it to follow a running import; open a batch for its counts (read and saved), files and the list of errors and warnings.

StatusMeaning
Pending · In progressWaiting or running
SuccessEvery record saved
Completed with issuesSaved, with warnings or errors listed on the batch
FailedNothing usable was saved; read the errors

6. Search Households and Individuals

  • Households: filter by household code (REGISTRATIONNO). The household page shows its details (size, status, phone, wave) and its members with role, NIN, Prem No. and the recipient.
  • Individuals: filter by first and last name, NIN, Prem No., phone and gender. The person's page shows personal details, disability, facility, the NIDA verification and School Information System data recorded in PSSN II.

Both pages also show the raw record as it came from PSSN II, for checking.

7. Troubleshooting

ProblemWhat to do
“Missing required column(s)”Export again with the template's columns.
An API import stays In progressLarge districts take time; refresh later. If it stops, start it again for that district.
A person is not found in the live RegistryArchive records never enter the live registry; use the Registry module's imports for live data.
