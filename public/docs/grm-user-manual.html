1. Purpose, Roles, and Access

The Grievance module records complaints or concerns, identifies the reporter when known, assigns work to staff, preserves comments and evidence, and tracks the grievance through closure.

Typical user roles

RoleTypical work
Intake officerCreate grievances and search existing records.
ProcessorReview assigned grievances, update status, comment, resolve, close, and reopen.
SupervisorProcessor functions plus oversight and reporting, subject to deployment.
Reviewer (read-only)Search and open read-only grievance details.

Access & permissions

Menus and controls are permission-based. If an action is missing, do not use another person's account — ask the system administrator to review your assigned role. The standard processor bundle is rights 127000, 127002, 127004, 127005, 127006. Add 127001 only where uploads to existing tickets are required; it also grants creation.

RightGrants
127000Search and open grievance records (and the Grievance menu).
127001Create grievances and upload attachments to existing tickets.
127002Update grievances — edit fields and change status.
127004Add comments to a grievance.
127005View the full comments table.
127006Resolve grievances (resolve-using-comment and close).

2. Module Navigation and Key Concepts

Open the main Grievance menu. Depending on your rights it can contain:

  • Add Grievance — register a new grievance.
  • Grievances — search, open, and process records.
  • Grievance Categories, Types, and Channels — configuration lists, normally maintained by administrators.
  • Grievance Reports — report shortcuts when enabled in the deployed build.

Status lifecycle

StatusMeaning
RECEIVEDThe grievance has been registered.
OPENThe grievance is accepted for active handling.
IN_PROGRESSWork is actively underway.
RESOLVEDA resolution has been recorded.
CLOSEDProcessing is complete and the record is locked.

Reporter types

Reporter typeWhen to use

Attending StaffA system user reports the grievance.
NoneThe grievance is anonymous or no reporter record is available.

3. Register a Grievance

Before you start

  • Confirm whether the grievance already exists.
  • Collect the reporter's consent and only record information required for handling the case.
  • Prepare supporting files. A grievance can have up to 5 attachments, each no larger than 25 MB.
  • Know the correct category, type, intake channel, and assigned staff member.

Registration procedure

  1. Open Grievance > Add Grievance.
  2. Select the Reporter Type. For Individual or Beneficiary, select the matching registry record. For Attending Staff, select the system user. Choose None for an anonymous grievance.
  3. Select the Category. The Type list is restricted to types configured under that category.
  4. Select the Type and confirm the Channel (the reviewed build defaults the channel to Web).
  5. Enter the Date of Incident when known. Future dates are not permitted.
  6. Assign the grievance to the responsible User where applicable.
  7. Enter a concise but complete description. Separate facts, reported allegations, and actions already taken.
  8. Select supporting files if needed. Review filenames before saving.
  9. Select Save and wait for the activity journal to confirm successful creation.
  10. Open Grievances and search for the generated code to verify the record exists.
Payment-related categories. When a category name contains Payment or Malipo, the form can require a payment window and payment year — complete both fields before saving.

4. Search, Open, and Review Grievances

Open Grievance > Grievances. Use one or more filters, then select Search.

Open a grievance

  1. Search using the grievance code or another filter.
  2. If you have edit rights, select the Edit action in the row.
  3. If you are a read-only reviewer, double-click the row to open the details.
  4. Check the reporter, category, type, status, assigned user, description, resolution target, attachments, and comments.

5. Update Assignment, Status, and Details

A processor with update permission can change the category, type, incident date, status, assigned user, description, and resolution value. Reporter identity, priority, and channel are presented as read-only in the reviewed edit screen.

  1. Open the grievance from the search list.
  2. Review the current information before changing it.
  3. Update the assigned User when responsibility changes.
  4. Set Status to OPEN or IN_PROGRESS as processing begins.
  5. Update the description only to correct or clarify the main account — use comments for the ongoing case log.
  6. Select Save and confirm success in the activity journal.
  7. Search for the grievance again and verify the new status.
Audit discipline. Do not overwrite the description to hide previous information. Use comments for investigation notes and status explanations; historical versions can be reviewed with Show History.

6. Comments, Attachments, and Printing

Add a comment

  1. Open an active grievance.
  2. Scroll to Comments and select Add Comment to a Grievance.
  3. Enter the comment. Add a commenter type and record when required by local procedure.
  4. Select Save and verify that the comment appears.

Users with comment-create permission can add comments. The currently assigned user can also add a comment to their assigned grievance. Viewing the full comments table requires comment-view permission.

Attach additional evidence

  1. In the Attachments panel, select the upload icon.
  2. Choose allowed files. The module rejects files that exceed size, count, or MIME-type limits.
  3. Use Preview for images, audio, video, or PDF. Use Download for any stored attachment.
Existing-ticket uploads currently require the create/upload right 127001. If the upload control is unavailable or the request is denied, contact the system administrator.

Printing

Use the print icon in the grievance details to print the grievance. A separate print icon in the comments panel prints the comment history. Verify that confidential information is not exposed before printing.

7. Resolve, Close, and Reopen

Resolve using a comment

A user with comment-view and resolve rights can select the checkmark beside a suitable comment. The selected comment becomes the resolution comment and the tested workflow closes the grievance.

  1. Add a clear resolution comment that states the decision, action taken, and any follow-up.
  2. Select Resolve Using Comment beside that comment.
  3. Confirm that the grievance reaches its terminal status and becomes read-only.

Close by changing status

Changing status to CLOSED requires both update and resolve rights. The application requires a closing comment before the close operation is submitted.

  1. Change Status to CLOSED.
  2. Select Save.
  3. Enter the required closing comment in the dialog.
  4. Select Close Grievance and confirm that the record is locked.
Reopen. A processor with update rights can reopen a closed grievance using the unlock action. Reopen only when new evidence, an appeal, or an incomplete action justifies renewed processing — record the reason in a comment.

8. History and Reporting

Historical versions

  1. Open the Grievances search page.
  2. Select Show History and then Search.
  3. Open the required version. Historical versions are read-only.
  4. Compare the version with the current record and comments.

Reports

The module defines the following reports:

  • Grievance by Categories
  • PAAs without Grievances
  • Channels Received Grievances
  • Grievance Resolution Status
  • Grievance Closure Timelines
  • Grievance Closure Timelines by PAA
  • Overdue Grievances by PAA

Report filters include report type, date range, assigned agent, and PAA/location. The source supports CSV, Excel, and PDF export when results exist.

Data-protection practice

  • Use the least amount of personal data needed to process the grievance.
  • Do not place passwords, financial credentials, or unrelated medical details in comments or attachments.
  • Verify the correct individual or beneficiary before saving.
  • Do not export or print grievance data unless authorized.
  • Use anonymous reporter mode when identity is not known or should not be recorded under policy.
